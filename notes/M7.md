## Search Feature Plan

### Data Model
No changes required. Notes already have `title`, `body`, `tags`. Optionally `tags: [...]` and `created_at` could be added later for filtered/sorted results.

### Routes

**`app.py`**

1. `GET /search?q=` — new route
   - Strip and lowercase `q`
   - Empty/whitespace → `redirect(url_for('home'))`
   - Filter `app.notes`: match if `q` in `title.lower()` or `q` in `body.lower()` (treat `None` as `""`)
   - Build snippet per note: first ~150 chars of body, wrap match in `<mark>` tags (use `markupsafe.Markup` to safely inject HTML without double-escaping)
   - Render `search.html` with `results`, `query`, `count`

2. `GET /` — minor update
   - Pass `q=request.args.get('q', '')` to `home.html` so the search bar stays populated on return

### UI

**`templates/search.html`** — new file
- Nav with search bar (same markup as home)
- Heading: `N notes match "query"` or `No notes match "query"`
- Each result: note card with title + body snippet, matches in `<mark>`

**`templates/home.html`** — add search bar to nav
- `<form action="/search" method="GET">` with `<input name="q">`

**`templates/new_note.html`** — add same search bar to nav (shared nav pattern)

### Edge Cases handled
| Case | Handling |
|---|---|
| Empty/whitespace query | Redirect to `/` |
| XSS | `markupsafe.Markup` + `escape()` — never render raw user input |
| Case sensitivity | `q.lower()` vs `field.lower()` |
| `None` title/body | `(field or "").lower()` |
| No notes at all | Friendly prompt in `search.html` |
