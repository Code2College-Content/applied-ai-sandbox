# M7 — Multi-Tool Workflows

## Feature I picked
- Note pinning: pinned notes float to the top of the home list.

## Plan from chat

### Data-model changes
- Add `"pinned": False` as a default key on every note dict created in `new_note()`.
- No new storage structure needed — one boolean on the existing in-memory dict.
- `app.notes` stays in **insertion order** in storage; sorting happens at render time only. This protects existing index-based routes (delete) from breaking when display order changes.

### Route changes
- **`home()` route** — before passing notes to the template, build a display list: pinned notes first, then unpinned, but carry along each note's **storage index** so action URLs stay correct.
- **New `POST /notes/<idx>/pin` route** — toggles `app.notes[idx]["pinned"]` and redirects to `/`. GET returns 405; out-of-range index returns 404. Same shape as the delete route.

### UI changes
- Each note card gets a small pin form posting to `/notes/<storage_idx>/pin` with a button labeled **"Unpin"** if pinned, **"Pin"** if not.
- Pinned cards get a visual marker (a `📌` or a CSS class like `pinned`) so they're distinguishable at a glance.
- Render a `<h2>Pinned</h2>` divider before pinned cards and `<h2>Notes</h2>` before unpinned — only when both groups are non-empty.

### Edge cases to handle
| Case | Expected behaviour |
|------|--------------------|
| All notes pinned | Entire list renders as pinned; no empty unpinned section shown |
| No notes pinned | Normal list; no "Pinned" header rendered |
| Pin/unpin the only note | Works; card moves to the correct section |
| New note added while others are pinned | New note has `pinned: False`, appears at bottom of unpinned section |
| Delete a pinned note | Uses storage index, not display index — works correctly |
| Display index ≠ storage index | Template must receive storage indices for action URLs, not loop indices — otherwise pin/delete silently operate on the wrong note |
