## Plan from chat
- Feature: A "starred" filter (toggle to show only starred notes)
- Plan;pt679: **Starred filter — implementation plan**

**Data model (`app.py`)**

When creating a note at line 29, add `"starred": False` to the dict. That's the only data change. No migration, no backfill — the list resets on restart anyway.

**Routes (`app.py`)**

Update the GET `/` route to read `request.args.get('starred')`. If present, filter `app.notes` down to only dicts where `starred` is `True` before passing the list to the template. Also pass a `show_starred` boolean so the template knows whether the filter is active.

Add a new POST `/notes/<int:idx>/star` route. It flips `app.notes[idx]['starred']` to its opposite, then redirects back to `/`. If the filter was active when the user clicked the star, preserve `?starred=1` in the redirect so they land back on the filtered view. Guard against an out-of-range index with `abort(404)`.

**Templates (`home.html`)**

Add a filter toggle link near the top of the note list. When `show_starred` is `False`, it links to `/?starred=1`. When `True`, it links to `/` (to clear the filter). Style the active state differently so it's obvious the filter is on.

Add a small `<form method="POST" action="/notes/{{ loop.index0 }}/star">` next to each note. The submit button shows a hollow star (☆) when unstarred and a filled amber star (★) when `note['starred']` is `True`.

Add an `{% if notes %} … {% else %}` block. When the starred filter is active and the list is empty, show a message like "No starred notes yet — click ☆ on any note to star it." Don't show the empty state when the filter is off and there are simply no notes at all (that's a different state the app may already handle).

**Edge cases**

- POST to `/notes/99/star` when fewer notes exist → `abort(404)`, don't let Python raise an unhandled `IndexError`.
- User unstars a note while `?starred=1` is active → the redirect should return them to the filtered view, where that note is now correctly absent.
- Check `tests/conftest.py` for any fixture that manually constructs a note dict. If any do, add `"starred": False` to those dicts so the template doesn't throw a `KeyError` when it reads `note['starred']`.

**Tests (`tests/test_task_03.py`)**

- Create a note, assert `app.notes[0]['starred']` is `False` by default.
- POST to `/notes/0/star`, assert it flips to `True`. POST again, assert it flips back to `False`.
- Create two notes, star one. GET `/?starred=1`, assert only the starred note appears in the response HTML.
- Create a note, don't star it. GET `/?starred=1`, assert the empty-state message appears in the response.
