## 5-step framework

1. Define done — describe the concrete end state (a user can do X and see Y; existing tests still pass), not "the feature works."
2. List the components — the files, routes, tables, templates, and tests that must exist.
3. Order by dependency — what has to exist before what (model before route, route before template).
4. Define each step in isolation — input (what state is the repo in?), action (what does Claude do?), output (what changed and what verifies it?).
5. Insert checkpoints — between steps, one sentence on how you will manually verify before moving on. Aim for 6 to 10 steps.

## Decomposition

Feature: tags on notes. The sandbox stores notes as an in-memory list of dicts
({"title": ..., "body": ...}), so tags are a new key (list of strings) on that
dict, not a separate model.

1. Add a tags key to the note dict. In the /notes/new POST handler, build the note as {"title": ..., "body": ..., "tags": []} so every note carries a list of strings that defaults to empty. Verify: existing tests still pass, and after adding a note via the form with no tags, app.notes[-1]["tags"] == [].

2. Add a parse_tags helper in app.py that turns a comma-separated string like "work, urgent" into ["work", "urgent"], trimming whitespace and dropping empty entries. Verify: a pytest case, e.g. parse_tags("work, , urgent ") == ["work", "urgent"].

3. Add a tags text input to new_note.html (comma-separated) and wire the POST handler to call parse_tags on it and store the result on the note dict; preserve the typed value on a validation error the same way title and body already are. Verify: submitting title + body + "work, urgent" yields app.notes[-1]["tags"] == ["work", "urgent"], an empty tags field yields [], and a failed submit keeps the typed tags in the form.

4. Render tag chips next to each note title in home.html, guarding the empty case so untagged notes show nothing, with a small chip CSS style. Verify: a tagged note shows chips, an untagged note shows none, and existing notes still render.

5. Update home() to read ?tag= from the query string, filter app.notes to notes containing that tag (missing or empty means all notes), and pass the sorted set of unique tags to the template. Verify: /?tag=work returns only work-tagged notes, / returns all notes, and an unknown tag returns an empty list.

6. Add a filter bar above the list in home.html: an "All" link to / plus one link per unique tag pointing to /?tag=<value>, marking the active one. Verify: clicking "work" loads /?tag=work and the list narrows to work-tagged notes; clicking "All" restores the full list.

7. Add tests/test_task_03.py covering parse_tags, the save path (a POST stores the parsed list on the note), and the filter (GET /?tag=work returns only matching notes). Verify: pytest passes the new tests and the existing suite (the pre-existing test_task_02 failures are unrelated to tags).
