## Task 3 — what happened
  Plan: Tag Filter Feature

 Context

   The notes app already parses comma-separated tags and stores them as a list on each note (implemented in M5 Task 1). The next step is to make tags useful by letting the user filter the notes list to only show notes matching a selectedag. This adds a clickable tag filter UI to the home page.

-
anges

 1. app.py — filter notes in the home route

   Read the optional ?tag= query parameter. If present, filter app.notes to notes whose tags list contains that value. Collect all unique tags across all notes to populate the filter buttons. Pass notes, all_tags, and active_tag to the template.

   @app.route("/")
   def home():
       tag_filter = request.args.get("tag", "").strip()
     notes = [n for n in app.notes if tag_filter in n["tags"]] if tag_filter else app.notes
       all_tags = sorted({t for n in app.notes for t in n["tags"]})
       return render_template("home.html", notes=notes, all_tags=all_tags, active_tag=tag_filter)

   2. templates/home.html — filter buttons + tag display on cards

   CSS additions (inside the existing <style> block):
   - .tag-bar — flex container for filter pills
   - .tag-pill — base style for clickable tag button (rounded, light gray background)
   - .tag-pill.active — highlighted style for the currently selected tag (dark blue, white text)

   Filter bar (between the "+ New note" button and the notes list):
   - "Filter by tag:" label
   - "All" link → /? (clears the filter); active when active_tag is empty
   - One pill per tag in all_tags → /?tag=<tag>; active when it matches active_tag
   - Only render the bar when all_tags is non-empty

   Note cards — below the body <p>, add a small tag display:
   {% if note.tags %}
     <p class="note-tags">
       {% for t in note.tags %}
         <a class="tag-pill {% if t == active_tag %}active{% endif %}" href="/?tag={{ t }}">{{ t }}</a>
       {% endfor %}
     </p>
   {% endif %}
