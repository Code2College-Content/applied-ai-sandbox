## Bug hunt #1 — SQL injection

**Bug:** The query directly interpolates user input into the SQL string, making it vulnerable to SQL injection attacks.

**Why Claude wrote it:** It likely followed a simple, "looks correct" SQL example where string formatting is used for readability instead of parameterized queries.

**Fix:** Use parameterized queries to safely bind user input.

```python
rows = db.session.execute(
    "SELECT id, title FROM notes WHERE title LIKE :q",
    {"q": f"%{q}%"}
).fetchall()
```

## Bug hunt #3 — edge case

**Bug:** The function crashes with a `ZeroDivisionError` when given an empty list.

**Why Claude wrote it:** It assumed the input always contains values because the example test only covered non-empty cases.

**Fix:** Add a guard before dividing:
```python
if not ratings:
    return 0
```

**Bug:** The API key is hardcoded in the source code, exposing a sensitive credential.

**Why Claude wrote it:** It prioritized a "working example" over secure configuration practices, likely copying a quickstart-style snippet.

**Fix:** Move the key to an environment variable and rotate the exposed key immediately.
