## Bug hunt #1 — SQL injection
- Bug: User input is interpolated directly into the SQL string, letting an attacker inject arbitrary SQL — e.g. typing `' OR '1'='1` could expose or destroy data.
- Why Claude wrote it: String-formatted SQL looks plausible and matches older tutorials in Claude's training data. It pattern-matched to "how you query with a variable" rather than "the safe way to do it."
- Fix: Use a parameterized query so the database treats input as data, never as code:
```python
  rows = db.session.execute(
      "SELECT id, title FROM notes WHERE title LIKE :q",
      {"q": f"%{q}%"}
  ).fetchall()
```

## Bug hunt #2 — hallucinated package
- Bug: `flask_simpleauth` does not exist on PyPI. The code looks fine and may even pass a linter, but crashes at runtime with `ModuleNotFoundError`.
- Why Claude wrote it: Claude generated a plausible-sounding package name that matched the naming pattern of real Flask extensions (`flask_login`, `flask_wtf`, etc.). It hallucinated a library rather than admitting it wasn't sure of the exact name.
- Fix: Use the real package — `Flask-Login`:
```python
  from flask_login import LoginManager, login_required
```
  Install with `pip install Flask-Login`.

## Bug hunt #3 — edge case
- Bug: Calling `average_rating([])` raises `ZeroDivisionError` because `len([])` is 0. An empty list is a realistic input — any product or note with no ratings yet.
- Why Claude wrote it: Claude only tested the happy path it imagined. It wrote the function and the test together, so the test never challenged the function — it just confirmed the case Claude already had in mind.
- Fix: Guard against the empty case:
```python
  def average_rating(ratings):
      if not ratings:
          return None  # or 0.0 depending on what the caller expects
      return sum(ratings) / len(ratings)
```
  And add the missing test: `assert average_rating([]) is None`.

## Bug hunt #4 — hardcoded secret
- Bug: The real API key is hardcoded in source. The moment this is committed, it's exposed in git history forever — bots scan public repos for secrets within minutes of a push, and even deleting it in a later commit doesn't remove it from history.
- Why Claude wrote it: Claude was optimizing for working code and inlined whatever key value it saw in the conversation. It doesn't automatically treat secrets as different from other string values unless prompted to.
- Fix: Load from an environment variable, and if the key was ever committed, rotate it immediately in your OpenAI dashboard — removing it from code is not enough:
```python
  import os
  client = openai.OpenAI(api_key=os.environ["OPENAI_API_KEY"])
```
  Store the real value in a local `.env` file and make sure `.env` is in `.gitignore`.
