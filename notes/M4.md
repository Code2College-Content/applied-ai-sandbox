## Bug hunt #1 — SQL injection
- Bug: The search query 'q' is being turned directly into raw SQL strings using an f-string. This makes it so the user can directly inject SQL commands.
- Why Claude wrote it: F-strings are a natural way in Python to insert values into a string. It didn't account for a user inserting SQL commands.
- Fix: Parameterize it so the database treats q as a value, not code: `db.session.execute("SELECT id, title FROM notes WHERE title LIKE :q", {"q": f"%{q}%"})`

## Bug hunt #3 — edge case
- Bug: It crashes with ZeroDivisionError because `len([])` is 0 and you can't divide by zero.
- Why Claude wrote it: It tested with a normal list, but never accounted for empty lists. It verified the expected user paths.
- Fix: Check if 0: `return sum(ratings) / len(ratings) if ratings else 0.0`

## Bug hunt #4 — hardcoded secret
- Bug: It hardcoded the API, once it's commited, it will be in the history forever.
- Why Claude wrote it: It filled in a working example, using a placeholder that looks real. It did not flag that secrets need to stay out of code.
- Fix: Get the secret from a safe environment not in git (ex. .env files)
