# M4 — Reading and Verifying Output

## Bug hunt #1 — SQL injection
- Bug: User-controlled q is directly interpolated into the SQL string, which allows attackers to inject arbitrary SQL and execute it on the database.
- Why Claude wrote it: F-strings look natural in Python, so without explicit context, Claude assumed it was acceptable
- Fix: Use bound parameters or SQLAlchemy's query API so the database treats userinput as data

## Bug hunt #2 — hallucinated package
- Bug: Claude imported a package that doesn't exist.
- Why Claude wrote it: The name fits the patterns of Flask extensions and sounds right
- Fix: Use the real package, Flask-Login

## Bug hunt #3 — edge case
- Bug: ZeroDivisionError is raised by calledaverage_raiting([]) because it tries to do 0/0
- Why Claude wrote it: Claude only tested what would work and didn't consider realistic edge cases like an empty list
- Fix: Add a guard to and a test that checks if the list is empty before doing anything else

## Bug hunt #4 — hardcoded secret
- Bug: Claude hardcoded an API key directly into the code, as anyone with access to the repo can steal the key
- Why Claude wrote it: It was the literal value it saw, so it inlined it and probably didn't recognize that secrets shouldnt be commited to version control.
- Fix:  Load the key from an environment variable and rotate a leaked key
