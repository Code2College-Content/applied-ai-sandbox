## Bug hunt #1 — SQL injection
- Bug: The query is built with an f-string that drops the raw user input q straight into the SQL, so it is a classic SQL injection — a value like ' OR 1=1 -- or '; DROP TABLE notes; -- changes what the query does and lets an attacker read or destroy data.
- Why Claude wrote it: An f-string assembling a SQL string reads as clean, obvious code and mirrors countless tutorial snippets, and without the context that this is SQLAlchemy (which expects a text() construct with bound parameters) string interpolation looks like the natural way to insert the search term.
- Fix: Use a parameterized query — wrap the SQL in sqlalchemy.text() with a named placeholder (LIKE :pattern) and pass {"pattern": f"%{q}%"} as bound parameters, so the database treats q as data and never as executable SQL.
