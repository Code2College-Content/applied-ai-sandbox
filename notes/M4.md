# M4 — Reading and Verifying Output

## Bug hunt #1 — SQL injection
1. The bug is SQL injection. User input is inserted directly into the SQL query with an f-string.
2. Claude wrote it this way because raw SQL string formatting looks common in older examples online. Without ORM or parameterized query context, the code seems simple and plausible.
3. The fix is to use parameterized queries or SQLAlchemy ORM filtering instead of string interpolation. That prevents user input from changing the SQL command.


## Bug hunt #2 — hallucinated package
1. The problem is that flask_simpleauth is not a real installed package in the environment. Running pip show flask_simpleauth would likely return “Package(s) not found”.
2. Claude probably hallucinated the package name because it sounds similar to real Flask auth libraries. The import pattern also looks believable from common Flask examples. 
3. The fix is to use a real authentication library like Flask-Login instead.

## Bug hunt #3 — edge case
1. Calling average_rating([]) causes a ZeroDivisionError. The function divides by len(ratings) when the list is empty.
2. Claude missed the edge case because its test only used normal input with values present. The generated test matched the implementation instead of challenging it.
3. The fix is to handle empty lists before dividing. For example, return 0, None, or raise a custom error if ratings is empty.

## Bug hunt #4 — hardcoded secret
1. The API key is hardcoded directly into the source code. If the code is pushed to GitHub, the secret could be leaked or abused.
2. Claude wrote it this way because example snippets often inline fake API keys for simplicity. It copied the pattern without considering production security practices.
3. The fix is to store the API key in environment variables or a .env file. Then load it securely instead of committing secrets into the codebase.
