 ## Step 4 — good-context plan

The sandbox has a working in-memory notes app (register/login/logout not yet
present). The goal is to add authentication so each logged-in user sees only
their own notes.

Current state of the codebase

- app.py — Flask factory (create_app), in-memory app.notes: list[dict],
routes: GET /, GET/POST /notes/new. No auth at all.
- Templates: home.html, new_note.html — no base.html, no login/register.
- requirements.txt — only Flask==3.0.3 and pytest==8.3.3.
- tests/conftest.py — creates app and client fixtures, no auth setup.
- tests/test_task_01.py — currently passing (validation already in app.py).
- tests/test_task_02.py — currently failing (delete route not yet added).

Key constraint: keeping existing tests passing

test_task_01 POSTs to /notes/new without logging in. Adding @login_required
to that route would redirect those requests and break the tests. The fix:
only protect / with @login_required. Leave /notes/new open, as the
task spec only states "anonymous visitor going to / is redirected to /login."

Plan

1. requirements.txt — add dependencies

Flask-Login==0.6.3
Flask-SQLAlchemy==3.1.1
(werkzeug ships with Flask — no separate pin needed)

2. models.py — new file

Define User using SQLAlchemy + UserMixin:
- id, username (unique, non-null), password_hash
- set_password(pw) and check_password(pw) helpers using werkzeug

3. app.py — wire auth + update routes

Inside create_app():
- SQLALCHEMY_DATABASE_URI: default to sqlite:///notes.db; if
app.config["TESTING"] is set, override to sqlite:///:memory: so the
test fixtures get a fresh DB without touching conftest.py.
- Init SQLAlchemy(app) and LoginManager(app) with login_view = "login".
- Call db.create_all() inside with app.app_context() at the end of factory.
- Add @login_manager.user_loader.
- Add @login_required to home() only. Filter notes:
[n for n in app.notes if n.get("user_id") == current_user.id].
- In new_note() POST, stamp each new note with
user_id=current_user.id if current_user.is_authenticated else None.
- New routes: GET/POST /register, GET/POST /login, GET /logout.

4. New templates

- templates/login.html — extends base.html; username + password form.
- templates/register.html — extends base.html; same fields.

5. templates/base.html — new shared layout

Extract common <head> / styles from home.html. Add a <nav>:
- Authenticated: "Hi, {{ current_user.username }}" + Logout link.
- Anonymous: Login + Register links.
Update home.html and new_note.html to {% extends 'base.html' %}.
