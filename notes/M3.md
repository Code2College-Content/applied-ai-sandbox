 2 — models.py (new)

 Simple Python class; no ORM. Uses sqlite3 directly to match the project's minimal style.

 from flask_login import UserMixin
 from werkzeug.security import generate_password_hash, check_password_hash

 class User(UserMixin):
     def __init__(self, id, username, password_hash):
         self.id = id
         self.username = username
         self.password_hash = password_hash

     def check_password(self, password):
         return check_password_hash(self.password_hash, password)

     @staticmethod
     def get_by_id(db, user_id): ...      # SELECT WHERE id=?
     @staticmethod
     def get_by_username(db, username): ... # SELECT WHERE username=?
     @staticmethod
     def create(db, username, password): ... # INSERT, return new User

 3 — app.py changes

 New config key: DATABASE (default "notes.db"; tests override with ":memory:").

 New helpers inside create_app():
 - get_db() — open a sqlite3 connection stored in g, close on teardown
 - init_db() — CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, username TEXT UNIQUE NOT NULL, password_hash TEXT NOT NULL)

 LoginManager wiring:
 login_manager = LoginManager()
 login_manager.login_view = "login"

 @login_manager.user_loader
 def load_user(user_id):
     return User.get_by_id(get_db(), int(user_id))

 New routes:
 - GET /login → render login.html
 - POST /login → validate credentials, login_user(user), redirect /; on failure re-render with error
 - GET /register → render register.html
 - POST /register → check username not taken, User.create(...), login_user(user), redirect /; on failure re-render with error
 - GET /logout → logout_user(), redirect /login

 Modified routes (add @login_required):
 - / — protected; filter notes: [n for n in app.notes if n.get("user_id") in (None, current_user.id)]
 - /notes/new — protected; on POST append {"title": ..., "body": ..., "user_id": current_user.id}
 - /notes/<idx>/delete — protected (existing Task 02 route)

 Why in (None, current_user.id) for the home filter:
 All notes created through the web UI will have user_id set (because the route is now protected). Notes seeded directly in tests via app.notes.append({...}) have no
 user_id. Showing user_id=None notes to any logged-in user is invisible in production (no such notes exist) and keeps the existing Task 02 home-page test green.
